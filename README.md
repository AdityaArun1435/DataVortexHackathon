# Data Vortex — Round 1 (Aaruush '26)

Phase 1 submission: recovering and cleaning the corrupted Social Engine dataset.

## Files
- `Social_Engine_Posts_Corrupted.csv` / `Social_Engine_Users.csv` — raw data recovered from node_07
- `clean_pipeline.py` — full cleaning script, run with `python3 clean_pipeline.py`
- `cleaned_posts.csv` / `cleaned_users.csv` — cleaned output (12,000 / 1,500 rows)
- `cleaning_log.txt` — plain-text log of every transformation applied, generated by the script
- `eda_report.md` — write-up of findings from the cleaned data
- `eda_charts.png` — platform volume, posting trend, engagement, and language distribution charts

## What was wrong with the data
- 360 exact duplicate rows in posts (dropped)
- Timestamps mixed across 3 formats: Unix epoch, DD-MM-YYYY, ISO 8601 (normalized to one datetime column)
- 1,784 missing `platform` values (filled as `"Unknown"`, not guessed)
- Missing/literal-`"NULL"`-string `text_content` (normalized to real NaN, left missing where genuinely absent, no fabrication)
- HTML-escaped text (`&amp;` etc., unescaped)
- 509 negative `likes` values, impossible for a like count (treated as corrupted, imputed with platform median, flagged in `likes_imputed`)
- Users table was verified clean on load: no nulls, no duplicates, referential integrity with posts holds

## How to run
```bash
python3 clean_pipeline.py
```
Requires `pandas`, `numpy`.

## Key finding
Engagement metrics (likes/shares/comments) show near-zero correlation with each other or with follower count, consistent with the dataset being synthetically generated rather than reflecting real engagement dynamics. Full details in `eda_report.md`.
